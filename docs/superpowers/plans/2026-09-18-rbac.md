# KSI-CCTV RBAC 구현 계획 (승인됨)

> **For agentic workers:** subagent-driven-development로 실행. 각 Task는 Developer 수정 → Test Runner 독립 검증 → Developer 커밋.

**Goal:** 오프라인 어플라이언스 콘솔을 3역할(관리자·관제원·뷰어) 다중 사용자로 확장하고, 감사 로그·인시던트 조치에 행위자(actor)를 기록한다. 기존 단일 관리자와 완전 호환.

**Architecture:** 접근법 A — 웹 계층 파일기반 사용자 저장소(`data/users.json`) + 콘솔 레벨 역할 강제(`proxy.ts` + `requireRole`) + 엔진 `X-KSI-Actor` ContextVar → `write_audit`. 엔진 단일 API 키 경계 유지.

**Spec:** 별도 spec 파일은 Plan 소관(Build 쓰기 차단 확인). 승인된 설계는 아래 §설계 요약과 대화(2026-09-18)에 기록.

## 설계 요약 (사용자 승인본 2026-09-18)

- **역할 서수**: `admin(3) > operator(2) > viewer(1)`. 상위는 하위 포함.
- **권한 행렬**: viewer=실시간·이벤트·인시던트·카메라/관측/텔레메트리 조회. operator=+알람 확인·인시던트 조치·카메라 CRUD/구역/적용/ONVIF. admin=+모델·사용자·시스템·파이프라인 제어·커미셔닝·감사·알림 설정.
- **관리자 = 기존 단일 관리자(무변경)**: `data/auth.json`(local) 또는 env 경로 유지, 사용자명 없음(감사 `admin`). 마이그레이션 없음.
- **관제원/뷰어 = `data/users.json`**: `{version:1, users:[{id, username, role, passwordHash, salt, enabled, createdAt, updatedAt}]}`. username `^[A-Za-z0-9._-]{1,64}$`·중복 금지, role ∈ {operator, viewer}, 비밀번호 12자+·공백 금지, 0600/0700, lock 원자쓰기.
- **세션**: 파일 내용 `{"exp", "userId"}` JSON, 기존 평문 epoch는 admin으로 하위호환. `sessionPrincipal(token) → {role, userId?} | null`(역할은 매 요청 재해석 — 변경·비활성 즉시 반영). `verifySession`(bool) 호환 유지.
- **로그인**: username 선택 필드 — 비우면 admin 경로, 입력 시 users.json 검증 → 개인 세션.
- **강제 2계층**: `roles.ts` 선언 맵 + `proxy.ts` 게이트(a: 페이지 미달 → `/`, `/api/*` → 403) + `requireRole(minRole)`(b: 변경 핸들러 방어심층).
- **감사 actor**: 콘솔 `engineWrite/engineGet` → `X-KSI-Actor` 헤더(서버 전용) → 엔진 ContextVar(`src/api/actor.py`) → `write_audit` actor 필드(기본 `system`). 32개 호출부 무수정. 인시던트 조치 기록에도 actor.
- **UI**: `/settings/users`(admin) 사용자 CRUD, 로그인 username 필드, 내비 역할별 숨김.
- **범위 외**: 카메라별 제한, 커스텀 역할, SSO/IdP, 2FA, 자가복구, 세션 관리 화면.
